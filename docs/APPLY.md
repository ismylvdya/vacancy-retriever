# Отклик одной кнопкой: сайдбар, резюме, письмо, Obsidian, Google Drive

## Что видит пользователь

В ленте `▶` (или кнопка *Apply*) — вакансия получает статус *Applied* и попадает в **сайдбар справа**.
Через ~8 секунд (окно для *Undo*) начинается обработка; в строке сайдбара крутится индикатор и видно, на каком
шаге работа. Когда всё готово, у строки появляются кнопки:

| Кнопка | Что делает |
|---|---|
| **Show PDF** | показывает PDF резюме в Finder (`~/Downloads`) |
| **Cover letter** | копирует сопроводительное письмо (в нём уже ссылка на PDF в Google Drive) |
| **Obsidian** | открывает заметку вакансии в Obsidian (там и ссылка на папку Drive) |
| **Stop** | (в работе) остановить; в сайдбаре плашка Stopped |
| **Retry** | (при ошибке) продолжить с шага, на котором остановились |
| **×** | убрать строку из сайдбара (файлы, заметка и папка остаются) |

С PDF и письмом остаётся откликнуться на сайте работодателя.

## Not now (N)

«Not now» тоже кладёт вакансию в Obsidian, но только заметку: статус «не сейчас», «👾FK» пустой, без «### моё»,
и один небольшой вызов Claude (модель scoring, Haiku) — навыки вакансии в «👾необходимые скилы». Без резюме, письма
и Drive. Готовая заявка Not now сама уходит из сайдбара (в работе, с ошибкой или остановленная — видна). Нажмёшь
потом ▶ — та же заметка становится откликом: статус «откликнулся», «👾FK», раздел «### моё» с письмом. Перевёл
отклик в Not now — отклик останавливается, сделанное остаётся.

## Stop и Undo

Кнопка **Stop** у заявки в работе и **Undo** ▶ / N делают одно и то же: заявка останавливается (идущий вызов Claude
дорабатывает, дальше ничего), в сайдбаре плашка **Stopped**; Retry продолжает с того же места, × убирает строку.

## Шаги (конвейер одной заявки)

```
 ▶ Apply ─► queued ─(8 с)─► 1. note ─► 2. folder ─► 3. materials ─► 4. pdf ─► 5. upload ─► 6. finalize ─► done
                            Obsidian   Drive        LLM по скиллу    build.py   Drive        письмо + ссылка,
                            заметка    папка        resume-tailor     (XeLaTeX)  PDF          заметка дополняется
```

1. **note** — заметка в Obsidian: свойства, ссылки, описание вакансии. Без LLM.
2. **folder** — папка вакансии в Google Drive (внутри общей папки приложения, доступ «по ссылке — читатель»).
3. **materials** — **один** вызов LLM (по умолчанию Sonnet по подписке): на входе инструкции скилла
   `resume-tailor` (`SKILL.md`, `references/letters.md`, `references/projects_facts.md`), вывод `build.py catalog`
   и текст вакансии; на выходе JSON — `selection` (для `build.py`), текст сопроводительного письма и 5–10 ключевых
   навыков вакансии (для свойства заметки). Агент с инструментами не запускается: так дешевле (~9–10 тыс. токенов
   входа на вакансию) и предсказуемо. Скилл остаётся источником правды: его файлы читаются при каждом вызове.
4. **pdf** — `python build.py build selection.json --out data/applications/<id>/` (скилл сам подбирает поля под
   одну страницу). Нужен `xelatex` (см. «Что нужно настроить»).
5. **upload** — PDF в папку вакансии на Drive (`drive.stub: true` — заглушка: явно фальшивые ссылки
   `https://drive-stub.invalid/…` и предупреждение; такое письмо не отправлять).
6. **finalize** — в письме строка `Резюме: ❗️…ВСТАВИТЬ…❗️` заменяется ссылкой на PDF; заметка дополняется
   письмом, навыками и ссылкой на папку. Выполняется всегда (дёшево и идемпотентно).

### Надёжность: перезапуск и лимиты

- Состояние каждой заявки — в таблице `applications` (SQLite): `state` (`queued` / `working` / `waiting` /
  `failed` / `done` / `cancelled`), текущий `step` и **результат каждого шага** (путь заметки, id папки, JSON
  материалов, путь PDF, id файла на Drive). Шаг считается сделанным, если его результат записан, — поэтому любой
  повтор начинает с первого несделанного шага, ничего не создаёт дважды и не тратит токены повторно.
- **Перезапуск приложения:** заявки в `working` при старте возвращаются в `queued` и продолжаются.
- **Падение между «создал» и «записал в базу»:** Drive ищет свои папку/файл по скрытым меткам
  (`appProperties`: `vr_vacancy`, `vr_pdf`), заметка — по свойству `retriever_id`. Дубликатов не будет.
- **Кончился лимит Claude** (`LlmError.kind == "limit"`): `waiting`, повтор через `retry_minutes`
  (по умолчанию 30) или по кнопке *Retry*. Другие ошибки — `failed` с текстом ошибки и *Retry*.
- **Undo** в течение 8 секунд — заявка удаляется, ничего не создано. Позже — помечается отменённой; созданное
  (заметка, папка) остаётся, строку можно убрать крестиком.
- Обрабатывается одна заявка за раз (Air 8 ГБ: каждый вызов claude CLI — отдельный процесс).
- Google Drive не подключён — шаги 2 и 5 пропускаются, заявка завершается с предупреждением «Drive not
  connected», в письме остаётся маркер `ВСТАВИТЬ`. После подключения *Retry* доделает папку, загрузку и письмо.

## Заметка в Obsidian

Формат как у существующих заметок-вакансий в vault (тег `👾травля`, `👾что_это: 📋 вакансия`), шаблон
пользователя (28.10.2026):

```markdown
---
tags:
  - 👾травля
👾что_это:
  - 📋 вакансия
начало: 2026-10-28       ← день, когда нажат ▶
👾статус:
  - откликнулся          ← obsidian.status в apply.yaml
👾где:
  - "🇷🇺яз: удаленка"     ← ровно одно из пяти: 🇺🇸 / 🇷🇺яз × в Сербии очно (и гибрид) / удаленка; 🇷🇺яз: очно в 3-ей стране
👾лэйблы:
  - 📋не IT              ← только для категорий kind: manual (rules.yaml)
👾FK: "[[Яндекс]]"        ← только если в vault есть заметка-работодатель с таким именем или алиасом
👾необходимые скилы: Python, SQL, Airflow, A/B testing
retriever_id: 123
---
### описание вакансии
[эта вакансия на сайте LinkedIn](https://www.linkedin.com/jobs/view/4480236338/)   ← каждый источник вакансии
[эта вакансия на сайте Citrus Systems](https://citrus.careers-page.com/jobs/…)     ← страница работодателя (Google for Jobs)

**описание вакансии:**
```
…полный текст вакансии…
```

### моё
[папка на Google Drive](https://drive.google.com/drive/folders/…)

**cover letter:**
```
…сопроводительное со ссылкой на PDF резюме на Drive…
```
```

- **Имя файла = имя заметки:** «<вакансия> • <работодатель> 🦆.md» (🦆 в конце = создана приложением, лэйбла нет) (недопустимые для файлов символы убираются). Если
  такое имя уже занято другой заметкой, добавляется номер перед 🦆: «… 2 🦆», «… 3 🦆» (у Obsidian нет своего механизма для файлов,
  которые создаёт не он сам; решение пользователя 28.10.2026). Переименовать можно: заметка находится по `retriever_id`.
- **Папка на Drive:** «<вакансия> • <работодатель> • <гггг-мм-дд> 🦆» в «👾 травля» (`drive.folder_name`).
- **Должность в именах — с грейдом** (`names` в apply.yaml): грейд intern / junior из фактов LLM даёт «Intern …» /
  «Junior …», если в названии его ещё нет (Junior, Intern, Trainee, стаж…, младш…); стажировка у российского
  работодателя (employer_type russian / ru_with_serbian_entity / intl_russian_speaking) — «<должность> стажа».
  Работодатель не известен — без разделителя: папка «Junior Data Analyst • 2026-10-29 🦆», заметка «Junior Data Analyst 🦆».
- **Служебных маркеров нет.** Блок «### моё» приложение переписывает, только пока в нём лежит его же текст
  (последний записанный хранится в базе, `applications.note_mine`). Изменили его руками или убрали заголовок —
  больше не трогается (в сайдбаре предупреждение). Свойства заполняются, только если пустые.
- Все значения — в `config/apply.yaml → obsidian`.

**Работодатель не известен:** «Unknown» не пишется нигде — в запросе к модели строки о компании нет, модель
получает правило (нейтральное приветствие, пустой `company`), имя PDF без компании (`Ismailov_CV_DA.pdf`).

## Google Drive

Через Drive API v3 (обычный HTTP-клиент `httpx`, без новых зависимостей), OAuth «приложение для компьютера»,
доступ `drive.file` — приложение видит **только созданные им самим** папки и файлы и папку, которую пользователь
выбрал в окне Google Picker; остальной Drive ему недоступен.

```
My Drive / 👾 травля /                                    ← папка пользователя (публичная), выбрана на /drive/pick
              Data Analyst • Citrus Systems • 2026-10-29 🦆/  ← папка вакансии (+ доступ «по ссылке — читатель»)
                 Ismailov_CV_Citrus_DA.pdf
```

Ссылка «[папка на Google Drive](…)» — в заметке («### моё»), ссылка на PDF — в письме. Выбор папки хранится в
`data/google_drive_parent.json`; пока её нет, шаг folder останавливается с подсказкой (Retry после выбора).

## Архитектура кода

```
src/vacancy_retriever/
  apply/                       backend отклика (не знает про веб)
    models.py                  Application, ApplicationState, Materials
    obsidian.py                ObsidianVault: поиск заметки/работодателя, создание, обновление блоков
                               NoteContent: рендер свойств и тела
    drive.py                   CloudFolders (интерфейс), GoogleDrive (API v3 + OAuth refresh), NoDrive
    google_auth.py             одноразовый вход: vacancy-retriever drive-login
    resume.py                  ResumeSkill (catalog / build через subprocess), MaterialsWriter (один вызов LLM)
    pipeline.py                DossierBuilder (вакансия → данные для шагов), шаги NoteStep … FinalizeStep,
                               ApplicationPipeline
    service.py                 ApplicationService (enqueue / withdraw / retry / dismiss), ApplicationWorker (поток),
                               сборка всего из конфигов, показ PDF в Finder
  storage/applications.py      ApplicationRepository (таблица applications)
  web/app.py                   /api/applications…; смена статуса на applied → enqueue, обратно → withdraw
  web/static/app.js            сайдбар (опрос /api/applications, кнопки)
config/apply.yaml              все настройки отклика
```

- Frontend (сайдбар) только показывает список и дёргает API; вся логика — в `apply/`.
- Воркер — фоновый поток в процессе сервера (`serve`); тесты его не запускают.
- Токены вызова `materials` пишутся в `llm_calls` со стадией `resume` (видно в Statistics).

## Что нужно настроить (один раз)

1. **TeX** для `build.py` скилла: Tectonic (`brew install tectonic`, без sudo; поставлен 28.10.2026). Приложение
   вызывает его через обёртку `scripts/tex/xelatex` (`resume.tex_bin_dir: scripts/tex`), кэш пакетов — в
   `.cache/tectonic` (первая сборка ~5 мин качает пакеты, дальше ~3 с). Подойдёт и свой XeLaTeX. Без него шаг `pdf` падает с
   понятной ошибкой «xelatex not found», остальное работает; *Retry* после установки.
2. **Google Drive:** console.cloud.google.com → новый проект → *APIs & Services* → включить **Google Drive API** →
   *OAuth consent screen* (External, добавить свой адрес в Test users) → *Credentials* → *Create credentials* →
   *OAuth client ID* → тип **Desktop app**. В `config/.env`: `GOOGLE_OAUTH_CLIENT_ID=…`,
   `GOOGLE_OAUTH_CLIENT_SECRET=…`. Затем `.venv/bin/vacancy-retriever drive-login` — откроется браузер, после
   согласия токен сохранится в `data/google_drive_token.json` (права только владельца).
   ⚠ Пока приложение в Google Cloud в статусе *Testing*, refresh-токен живёт 7 дней — переведите его в
   *In production* (Audience → Publish app; Branding нужно заполнить; проверка Google для `drive.file` не нужна).
   Папка для вакансий: включить **Google Picker API**, создать **API key** (ограничить: Google Picker API, сайты
   `http://127.0.0.1:18765/*`), вписать `GOOGLE_PICKER_API_KEY` в `config/.env`, открыть
   http://127.0.0.1:18765/drive/pick и выбрать папку.
3. **Vault:** `config/apply.yaml → obsidian.vault_dir` (сейчас `VAULT/chumbulev` в папке проекта).

## Открытые вопросы / дальше

- Разбор debug-жалоб на факты LLM — нужна боевая база с таблицей `reports` (в локальной копии от 13.10 её нет).
- Свойство `👾необходимые скилы` — строка через запятую (как просили); если удобнее список (чипсы в Bases) —
  одна настройка `obsidian.skills_as_list`.
- Когда пользователь реально откликнулся, можно ставить `👾статус: откликнулся` и `начало` из приложения
  (кнопка *Sent* в сайдбаре) — не сделано, сейчас это руками в Obsidian.

**Файлы резюме:** PDF собирается во временной папке и сохраняется только в `~/Downloads` (`resume.output_dir`;
имя занято другим файлом — «… 2.pdf»); в `data/` ничего не остаётся. Удалили PDF — кнопка «Rebuild PDF» в сайдбаре
соберёт его заново без LLM (подборка блоков хранится в базе).

## Статистика

Statistics → **Applies**: строка на каждый ▶ / N — время каждого шага (заметка, Drive, Claude, PDF, загрузка),
вызовы Claude этой заявки с моделями и токенами, доля 5-часового лимита Pro. Вызовы привязываются к заявке с
30.10.2026 (`llm_calls.application_id`), более ранние в эту таблицу не попадают.
