# Vacancy Retriever — справочник

Этот документ — для пользователя и для любого ИИ-ассистента, который видит проект впервые.
Если вы потеряли доступ к чату, где проект собирался, — всё нужное здесь.

## 1. Что это и зачем

Данила живёт в Белграде и ищет работу; главная цель — **ВНЖ в Сербии по работе**. Источников вакансий
около 45 (Telegram-каналы, сайты, почтовые рассылки), просматривать их руками каждый день невозможно.

Vacancy Retriever — локальное приложение для macOS. По кнопке **Start run** оно:
1. собирает новые вакансии из всех включённых источников;
2. отсеивает очевидный мусор дешёвыми правилами (без LLM);
3. отдаёт остальное LLM, которая **только извлекает факты** (категория роли, грейд, языки, юрлицо в Сербии…);
4. **код** по таблицам из `config/rules.yaml` решает группу, звёзды, ВНЖ и отсев;
5. показывает одну ленту, сгруппированную по жизненным приоритетам. Порядок групп и какие из них искать, выбирает
   пользователь (Settings → Feed groups, `rules.yaml → group_order` и `groups.N.enabled`); с 16.11.2026 первая — 7, потом 6:

| Группа | Что в ней |
|---|---|
| 7 | Офис или гибрид в Москве, IT/Data (`russia_office_cities`; город не назван — тоже сюда; решение 16.11.2026) |
| 6 | Удалёнка в России, IT/Data (страна — Россия, работодатель любой) |
| 1 | Сербия + ВНЖ, IT/Data (сербское юрлицо, в т.ч. российские компании с d.o.o.) |
| 3 | Русскоязычный работодатель, удалёнка, IT/Data, страна не Россия или неизвестна (без ВНЖ, но доход) |
| 2 | Сербия + ВНЖ, работа руками (дерево/мебель, производство, стройка, склад) |
| 4 | Сербия без ВНЖ (неофициально, «подмастерье») |
| 5 | Неясно (свёрнута) |

Номер группы — постоянный id (хранится в базе), порядок от него не зависит. Выключенная группа: её вакансии уходят в
Auto-skipped с причиной «Group off: …» (обратимо пересчётом), а источники, у которых в `sources.yaml → groups` только
выключенные группы, не опрашиваются. Группа известна лишь после оценки LLM, поэтому смешанные источники (RVC, письма,
большинство каналов) читаются всегда. `groups` источников заполнены 15.11.2026 по истории базы (группа учтена, если
показанных вакансий в ней больше 2; пусто — опрашивается всегда) и правятся в Settings → Sources.

Цель — утром за 10–15 минут просмотреть ленту и ничего не упустить; LLM тратит минимум токенов, а поломки
источников (блокировки, смена вёрстки) сразу видны.

## 3. Как устроен прогон

```
 Start run ──► 1. Сбор ────► 2. Дедуп сырых ─► 3. Предфильтр ─► 4. Докачка описаний ─► 5. LLM: факты
               (каждый        (та же ссылка,     (роли-стоп-слова  (только сайты из        (пачки по 10,
                источник       тот же текст,      заголовка,        detail_domains;         ≤2 параллельно)
                отдельно,      репост в другом    реклама RVC,      потом годы / грейд            │
                ошибка одного  канале — в LLM     старше 30 дн.)    без LLM, 3а)                  ▼
                не мешает)     не идёт)                                               Код: группа, звёзды,
                                                                                       ВНЖ, отсев (rules.yaml)
                                                                                                │
 Лента  ◄── 7. Коммит (одна короткая транзакция) ◄── 6. Дедуп вакансий (код + LLM для «серой зоны»)
```

- **3а. Опыт и грейд до LLM** (после докачки описаний, `Prefilter.check_requirements`): код ищет годы опыта в
  описании, названии и данных вверху страницы по приоритету `requirements.priority`; годы ≥ порога — отсев, годы
  меньше — дальше в LLM; лет нет нигде — отсеивает грейд (грейд сайта, грейд RVC, слова грейда в названии).
- Всё, что пишет прогон, помечено `run_id` и `staged=1`. Пока прогон идёт, лента показывает старые данные.
- **Коммит** — одна транзакция: staged → видимые, курсоры источников сдвигаются (только у собранных без ошибки),
  вакансии старше 30 дней уходят в Auto-skipped «Expired».
- **Отмена** (кнопка Cancel → второй клик) — всё с этим `run_id` удаляется, курсоры не трогаются. Остаются
  только записи о токенах (помечены «отменён»; токены прерванного вызова — «неизвестно»).
- **Сбой/сон ноутбука/kill** — при следующем старте незавершённый прогон считается отменённым.
- **Отказ LLM** (лимит подписки, сеть) — не провал: собранное сохраняется, неоценённые элементы ждут со
  статусом `pending_llm` и первыми идут в следующем прогоне; в шапке — «N items waiting for evaluation».
- **Курсоры:** Telegram — номер последнего поста; сайты и почта — время старта прогона минус 1 час.
  Первый прогон источника — за 1 день (`first_run_days`), дальше — с курсора.
- **Почта** помечается прочитанной и получает ярлык/папку `🦆 retrievered` **только после коммита** и только если
  все вакансии письма оценены.

## 4. Запуск и команды

```bash
scripts/start.sh          # сервер + иконка в меню-баре, открывает http://127.0.0.1:18765/
scripts/stop.sh           # остановить
```

Команды (из папки проекта):

| Команда | Что делает |
|---|---|
| `.venv/bin/vacancy-retriever run` | прогон из терминала (тот же конвейер, что кнопка) |
| `… run --sources serbiawork,habr --limit 10 --since 1d --db data/dev.sqlite` | быстрый отладочный прогон в отдельную базу |
| `… serve [--port 18765]` | только веб-сервер |
| `… menubar` | только иконка в меню-баре |
| `… check-sources` | быстрая проверка доступности всех источников (✓ / ✗ BLOCKED) |
| `… export-email-samples --limit 3` | сохранить образцы писем в `samples/emails/` (только чтение ящика) |
| `… recalculate` | пересчитать группы/звёзды по `rules.yaml` без LLM (или ссылка внизу ленты) |
| `… accreditation [--no-llm] [--registry-only]` | IT-аккредитация работодателей ленты сейчас / только скачать свежий реестр (docs/ACCREDITATION.md) |
| `… linkedin-exit` | проверить приватный выход для страниц LinkedIn (ни одного запроса к LinkedIn) |
| `… drive-login` | один раз подключить Google Drive для отклика (docs/APPLY.md) |

**Приложение для Launchpad:** `scripts/build-app.sh` собирает `build/Vacancy Retriever.app` (иконка —
`packaging/macos/icon.png`) и копирует его в `~/Applications` — это единственное, что проект кладёт вне своей папки.
Запуск приложения = `scripts/start.sh --no-open` (сервер + 🦆 в меню-баре, без значка в Dock); если всё уже запущено —
открывает ленту. Выключить всё — 🦆 → *Quit Vacancy Retriever* (останавливает и сервер). Путь к проекту зашит в
приложение: после переноса папки проекта — пересобрать. Лог запуска — `logs/launcher.log`.

**Автозапуск при входе в систему** (по желанию): Системные настройки → Основные → Объекты входа → «+» →
`~/Applications/Vacancy Retriever.app`.

## 5. Настройки (`config/`)

Все файлы проверяются при запуске; опечатка даёт понятную ошибку вида
`Configuration error: rules.yaml: categories.ds_ml.base: Input should be a valid integer`.

- **`sources.yaml`** — список источников. Поля: `id`, `type`, `name`, `url`, `enabled`, `max_pages`
  (предохранитель), `posts_per_day` (вес в прогресс-баре), `icon`, `params`. Внизу — `detail_domains`.
- **`rules.yaml`** — категории ролей (`kind`: it / manual / drop / hidden / other, `base`, `cap`), минусы к
  звёздам, грейды-отсев, названия групп, предфильтр (стоп-слова заголовка, правила RVC).
  После правки — `recalculate` (без LLM).
- **`llm.yaml`** — провайдер (`claude_sdk` / `anthropic_api` / `openai_api`), модели по этапам,
  `batch_size`, `max_concurrency`, обрезка длинных текстов, `effort`/`thinking`, цены (для оценки «сколько стоило бы по API», в интерфейсе не показываются).
- **`mail.yaml`** — ящики (Gmail, Яндекс), отправители и их парсеры, имя ярлыка.
- **`profile.md`** — резюме. Обновили резюме → следующий прогон оценивает по новому профилю.
- **`prompts/scoring.md`** — что LLM извлекает и как. Меняется без кода; категории должны совпадать с ключами
  `categories` в `rules.yaml`.

## 6. Как добавить / отключить источник

**Telegram-канал** — одна строка в `sources.yaml`:
```yaml
  - {id: new_channel, type: telegram, name: "Новый канал", url: "https://telegram.me/new_channel", posts_per_day: 3, max_pages: 5}
```
`id` = имя канала из ссылки. Всегда `telegram.me`, не `t.me` (в Сербии `t.me` не открывается).
Работает только для публичных каналов с веб-превью (`https://telegram.me/s/<канал>` открывается в браузере).
Группы (чаты) превью не имеют — их так не собрать.

**Отключить** любой источник: `enabled: false` и (для себя) `disabled_reason: "..."`.

**Новый сайт** — нужен сборщик: файл `src/vacancy_retriever/collectors/sites/<id>.py` по образцу соседних
(общие помощники — `sites/_common.py`: обход страниц с правилами остановки, `html_to_text`),
снимок страницы в `samples/html/<id>/` и тест `tests/test_site_<id>.py`. Затем строка в `sources.yaml` с
`type: <id>` и, если есть докачка описания, домен в `detail_domains`.

**Своя иконка источника:** положите `config/icons/<id>.png` (или `.svg`, `.ico`) — она важнее скачанной.
Или укажите путь в поле `icon:` (относительно `config/icons/`). Скачанные иконки лежат в `data/icons/` и
обновляются раз в ~30 дней.

## 7. Почта

1. Включите IMAP и создайте **пароль приложения**:
   - Gmail: myaccount.google.com → Безопасность → Двухэтапная аутентификация → Пароли приложений;
     Gmail → Настройки → Пересылка и POP/IMAP → включить IMAP.
   - Яндекс: id.yandex.ru → Безопасность → Пароли приложений → «Почта»; Почта → Настройки → Почтовые программы → IMAP.
2. Впишите в `config/.env`: `GMAIL_LOGIN`, `GMAIL_APP_PASSWORD`, `YANDEX_LOGIN`, `YANDEX_APP_PASSWORD`.
3. Проверьте: `.venv/bin/vacancy-retriever check-sources --sources gmail,yandex`.

Читаются только **непрочитанные** письма за 30 дней (отправитель сравнивается в приложении, а не поиском IMAP:
Яндекс не находит `hh.ru` в `noreply@hh.ru`). Во время сбора ящик не меняется (BODY.PEEK). Ссылки linkedin.com из
писем **никогда не открываются** — только показываются.

**Что бывает с письмом** (с 20.11.2026, подробно — `docs/STATUSES.md`):

| Письмо | LLM | Что видно в приложении | Что с письмом после прогона |
|---|---|---|---|
| известный отправитель, точный парсер нашёл вакансии | только эти вакансии | карточки | прочитано + `🦆 retrievered` |
| известный отправитель без вакансий (уведомление, незнакомый шаблон, отправитель без точного парсера) | разбор писем (Haiku) | статус → вкладка Statuses; волна стажировок / вакансии → лента; остальное — Processed → Hidden | прочитано + `🦆 retrievered` |
| неизвестный отправитель со словами про работу | разбор писем | то же | статус / волна / вакансии — прочитано + ярлык; не про работу — **не трогается** |
| неизвестный отправитель без слов про работу | нет | ничего | **не трогается** |

Ящик опрашивается, даже если все его группы ленты выключены (статусы от групп не зависят) — тогда его письма с
вакансиями остаются непрочитанными. Если LLM не уверена, что письмо — статус, оно всё равно показывается на вкладке
Statuses (с «?» или как *Unclear*).
Вакансия, уже собранная из другого письма (тот же id на сайте), второй раз не собирается.

**Отправители и парсеры (октябрь 2026):** LinkedIn job alerts / jobs / notifications / Premium (`linkedin`),
hh.ru (`hh_ru`: автопоиски и «Подходящие вакансии для резюме» — с 16.11.2026 читаются оба; подсказка «удалёнка» —
только если письмо так и пишет, адрес с метро («Москва, м. …») — подсказка «офис»; название автопоиска больше ничего не значит),
VK Internship (`vk_internship`: страница стажировки докачивается, «Набор закрыт» и офис в Москве/СПб отсеиваются
до LLM), Changellenge (`changellenge`: из дайджеста берутся только ссылки /vacancy/, офис вне Сербии — до LLM),
SuperJob (`superjob`), HR-платформа «Пульс» (`pulse`), Infostud (`infostud`), Технополис Москва (`newsletter`).
Без образцов — headhunter.ge/.kg и Хабр Карьера (`generic`, письмо целиком в LLM).
**Иконки:** на карточке у вакансии из письма — имя отправителя и его иконка со значком ✉️ (у Telegram — аватар
канала со значком Telegram). Иконка отправителя: файл `config/icons/mail-<icon>.png|svg` (LinkedIn, hh, SuperJob и «Пульс» лежат файлами:
linkedin.com не открываем, hh.ru отвечает 406), иначе favicon сайта из поля `site` в `mail.yaml`, иначе конвертик.
**Описания HH** догружаются с публичной страницы Get-Works по ID из письма перед оценкой вакансии. Текст берётся,
если в блоке описания есть ссылка с тем же ID HH. Запрос отправляется только на Get-Works, без авторизации и перехода
по редиректам. Если копии нет, вакансия оценивается по письму. При подготовке отклика приложение может повторить
поиск описания для ранее собранной карточки.
**Описания LinkedIn — через Google for Jobs** (`mail.yaml → linkedin_descriptions`, основной способ с 27.10.2026):
**ни одного запроса к LinkedIn**. Google for Jobs собирает вакансии с LinkedIn, Indeed, сайтов компаний; API JSearch
(openwebninja.com) и SerpApi отдают их с описанием (`collectors/job_search.py`). Ищем «название компания город»
(для Сербии — `country=rs` / `gl=rs`) и берём описание, только если это та же вакансия: ссылка в ответе с тем же
номером вакансии LinkedIn (другой номер — другая вакансия), а без такой ссылки — та же компания и то же название.
Нет совпадения — вакансия оценивается по письму («E-mail only»). Открываются только адреса API, ссылки из ответа —
никогда. Ключи `JSEARCH_API_KEY` / `SERPAPI_API_KEY` — в `config/.env`, в логи не попадают. Запросы считаются по
месяцам в `data/job_search.json`; провайдер останавливается на `max_per_month` (бесплатный тариф: JSearch Basic —
200 в месяц, SerpApi 100) и до конца прогона после 401/403/429. Второй провайдер спрашивается, только если
первый не ответил или исчерпал месяц (честное «не найдено» второй раз не ищется). Итог — пометкой у Gmail в
Statistics → Sources («found N, not found M»), отказ API — красным.

**Публичные страницы LinkedIn — запасной путь, по умолчанию выключен** (`mail.yaml → linkedin_public_pages`, подробно — `docs/LINKEDIN.md`). Отдельная красная секция Settings → *LinkedIn pages (proxy)*, вне кнопки Save: выключается одним кликом сразу (и останавливает уже идущий прогон перед следующей страницей), включается только когда задан прокси, он прошёл проверку прямо сейчас и фраза `ENABLE LINKEDIN` набрана вручную. Пока выключен, приложение к LinkedIn не обращается: вакансия, которую не нашёл Google for Jobs, сразу оценивается по письму. Когда включён:
Вакансия, которую не нашёл Google for Jobs, **ждёт вне ленты** и не раньше чем через день читается с публичной
страницы LinkedIn (как её видит человек без входа) — только через приватный выход приложения (резидентный прокси из
`LINKEDIN_PROXY_URL` в `config/.env` или свой VLESS-сервер через Xray), никогда с домашнего IP. Перед каждой страницей:
выход отвечает, он не домашний IPv4 и не в домашней IPv6-сети, не сменился за прогон. Не больше 12 страниц в день,
60–180 с между ними; первый отказ LinkedIn — пауза на 2 дня. Не нашёл никто или прошло 3 дня — вакансия оценивается по
письму («E-mail only»). Со страницы берётся и ссылка Apply на сайт работодателя (не открывается). Проверка выхода
без запросов к LinkedIn: `.venv/bin/vacancy-retriever linkedin-exit`. Statistics → Sources у Gmail — доли: Google
for Jobs / LinkedIn page / Not found / Waiting.
**Безопасность ссылок:** в письмах hh (`loginkey=`) и SuperJob (`?i=`) ссылки входят в аккаунт без пароля —
парсеры сохраняют только чистый адрес вакансии.

### Точный парсер письма (пошагово)

1. Сохраните образцы: `.venv/bin/vacancy-retriever export-email-samples --limit 3` (`--limit 0` — все непрочитанные)
   → `samples/emails/<отправитель>/*.eml`. Личные данные маскируются сами: адреса, телефоны, токены в ссылках, UUID
   и слова из `SAMPLE_MASK_WORDS` в `config/.env` (имя, фамилия). Всё равно просмотрите файл перед коммитом.
2. Скопируйте шаблон `parsers/_template.py` или похожий парсер (`hh_ru.py` — таблица, `vk_internship.py` — список +
   страница вакансии). Парсер возвращает список `ParsedVacancy(title, url, company, location, text, key,
   detail_url, extra)`, либо `raise IgnoreLetter("причина")` для известного шаблона без вакансий, либо
   `raise UnknownLetter(...)`. `key` — id вакансии на сайте (`hh:123`), `extra` — точные факты для LLM
   (`work_format`, `city`, `country`, `salary`). Страница вакансии — `@register_detail(имя)`, может вернуть
   `skip_reason` (отсев до LLM); домен — в `detail_domains` в `sources.yaml`.
3. В `config/mail.yaml` у отправителя: `parser: <имя>`.
4. Допишите образец в `samples/emails/expected.json` (сколько вакансий, или `"ignore"`), запустите
   `.venv/bin/python -m pytest tests/test_email.py tests/test_email_parsers.py`.

Можно попросить Claude: «пришли письма от X — разбери и напиши парсер» (см. этот раздел).

## 8. Как читать вкладки

**Feed** — только необработанные вакансии, по группам; внутри группы — соответствие ↓, при равных звёздах — категории
в порядке `rules.yaml → feed_category_order` (сначала ML, потом аналитика; решение 27.11.2026), потом дата ↓.
У вакансий российских групп (6, 7) — метка IT-аккредитации работодателя: зелёная *IT accredited*, оранжевая
*IT accreditation unknown*; компании точно без аккредитации — в группе 8 «Russia, no IT accreditation» внизу ленты,
она свёрнута (`docs/ACCREDITATION.md`). Туда же — вакансии, где работодатель частное лицо или ИП, название работодателя —
заглушка («крупный российский банк») или в тексте есть «ГПХ», «самозанятый» и т.п. (`no_it_accreditation_signs`; причина —
в подсказке метки). Фиолетовая *Internship wave* — анонс стажировки / набора / волны из любого
источника (пост, письмо, сайт), а не одна вакансия (`docs/PROGRAMMES.md`).
Каждая вакансия — одна строка с колонками: *Fit* (точки 1–5), *Role* (должность и работодатель),
*Permit* (в сербских группах: Yes / Likely) или *Country* (в остальных), *Format* (офис/гибрид/удалёнка и город),
*Salary* (только если в объявлении есть цифры), *Posted*. Синяя метка *Russian-speaking* — любая связь с русским: он в требуемых
языках, объявление на нём, русскоязычная команда, российский работодатель или слово из `russian_link_words` в тексте.
Оранжевая *English team* — такой связи нет, а английский требуется, это рабочий язык команды или компания международная.
Иначе языковой метки нет. *Informal* — только когда относится к вакансии; синяя точка — новое из последнего прогона.
Строка под фокусом раскрыта: саммари, основание ВНЖ, языки (если требуется не только русский), источники,
кнопки *Applied* / *Not now* / *Skip* (карточка уходит в Processed, внизу появляется *Undo*),
*Open source* (`Enter` на раскрытой карточке) — открыть сайт вакансии (первый источник); полный текст показывается при раскрытии по `Enter`.
Клавиатура: `J`/`K` (или ↑/↓) — по строкам, `▶` (стрелка вправо) Apply / `N` Not now / `◀` (стрелка влево) Skip, `Enter` — раскрыть
карточку с полным текстом, `Enter` на раскрытой — открыть сайт вакансии (первый источник), `Esc` — свернуть. Группу можно свернуть кликом по заголовку. Внизу — *Recalculate* (пересчёт по `rules.yaml` без LLM).
**Statuses** — статусы ваших откликов из почты (отказы, приглашения, тестовые, офферы), сверху новые, ниже
просмотренные; зелёный — прошёл этап, синий — нейтральное, серый — отказ, оранжевый — не уверены (`docs/STATUSES.md`).
**Шапка страницы** (прозрачная полоса во всю ширину окна, не зависит от сайдбара). Слева:
- **Undo / Redo** — отменить / повторить смену статуса (история живёт во вкладке браузера, переходы между Feed и
  Processed её не сбрасывают; Cmd+Z браузер перехватывает, поэтому кнопки);
- **шестерёнка** — экран настроек (ниже).

Справа — переключатель *Debug* и кнопка сайдбара *Apply* (с числом заявок). Большой заголовок уезжает при прокрутке,
тогда в шапке появляется маленький. Под шапкой прячется прокручиваемое, но видны фон страницы и заливка сайдбара.
Пока идёт Run, лента скрыта. Вкладки, подвкладки с фильтрами и заголовок группы / прогона остаются сверху при прокрутке.

**Настройки** (шестерёнка; закрыть — она же или `Esc`) — вместо страницы, разделы слева:
- **Fit (stars)** — дерево категорий ролей по типу (IT / Hands-on / Other / Skipped / Not a vacancy), у каждой база
  и потолок звёзд; штрафы. Справа — матрица звёзд выбранной категории для каждого сочетания фактов (совпадение стека ×
  язык команды × опыт), пересчитывается тем же движком прямо при правке; наведение на клетку показывает расчёт;
- **What is skipped** — годы важнее грейда, грейды, возраст, признаки «нет IT-аккредитации», офис вне Сербии, потолок
  зарплаты;
- **Feed groups**, **Pre-filter (no LLM)**, **Sources** (вкл./выкл.), **LinkedIn descriptions**, **LLM**, **Apply**.

Правки копятся; *Save* проверяет каждое значение и каждый файл той же валидацией, что при запуске, и ничего не
пишет, если что-то не так (подсветка у поля). Значения пишутся прямо в `config/*.yaml` точечно: комментарии и
выровненные таблицы не трогаются (`settings/yaml_patch.py`), поэтому правки видны в `git diff config/`. После
изменения правил лента сразу пересчитывается без LLM. Добавить настройку на экран — одно поле в `settings/schema.py`.

**Сайдбар** (справа, открывается кнопкой в шапке; секции *Generated* (готовые «▶» и N) и *Purgatory* (всё в работе; «▶» ждёт *Generate Obsidian note* (заметка всегда; галочки «CV» и «Cover letter», письмо только вместе с CV)) — и серая *Previous days* — всё до 3:00 сегодняшнего дня по местному времени, `apply.yaml → day_starts_at`; число на кнопке — две верхние секции; подробно `docs/APPLY.md`): `▶` / *Apply* ставит *Applied* и отправляет вакансию сюда. Через 8 с (окно для *Undo*)
после *Generate* приложение создаёт заметку в Obsidian, подбирает резюме и пишет сопроводительное по скиллу `resume-tailor`
(один вызов Sonnet), собирает PDF, кладёт его в папку вакансии на Google Drive и вставляет ссылку в письмо. Готово —
кнопки *PDF*, *Copy letter*, *Note*, *Drive*. Работа руками (`kind: manual`): только заметка с лэйблом «📋не IT» и письмом
на русском, без резюме, Drive и кнопки *PDF*. Переживает перезапуск и лимит Claude (*Retry*). Подробно и
настройка — `docs/APPLY.md`.

**Run ▾** — панель запуска: *Period* (за сколько суток, пусто = с прошлого прогона; каждый источник всё равно
продолжает с места, где остановился прошлый прогон), группы источников Telegram / Sites / E-mail и группы ленты на этот
прогон (только включённые в Settings): источники, дающие лишь снятые группы, в этот раз не опрашиваются, их позиция не
сдвигается — следующий прогон заберёт пропущенное. Выбор запоминается.
В раскрытой карточке — строка фактов: грейд, тип работодателя, язык объявления и требуемые языки флажками.

**Отсев по опыту и грейду** (решение 27.11.2026, `rules.yaml → requirements`, `scoring/requirements.py`): опыт и грейд
ищутся отдельно в трёх местах — описание (`text`), название (`title`), данные вверху страницы (`label`: теги T-Bank,
«Опыт работы» hh, грейд Habr / getmatch / geekjob / hirify, первая строка RVC; сборщики пишут их в `meta.page_meta`).
LLM возвращает найденное по местам (`experience_by`, `grade_by`), пропущенное в описании и данных страницы добавляет код
(`scoring/text_facts.py`, только у постов с одной вакансией). Решает первое место из `priority` (по умолчанию описание →
название → данные страницы); внутри места при нескольких значениях — меньшее («1–3 года» → 1, «Middle, Senior» → middle).
Годы важнее грейда (`years_over_grade`): если годы есть хоть где-то, решают только они (`experience_drop`: от 2 лет —
отсев); грейд (`dropped_seniority`, слова грейда в названии) отсеивает лишь вакансию без лет. Поэтому hh с «1–3 года» в
свойствах и без лет в описании проходит, а с «от 3 лет» в описании — нет. В Debug карточки строка *Requirements*
показывает, откуда взяты годы и грейд. Вакансии, оценённые до 27.11.2026, хранят один общий опыт и грейд — пересчёт
оставляет их как были.

**Звёзды:** объявление на русском — на звезду выше при прочих равных (`penalties.russian_ad_bonus`); международная компания без связи с русским — не больше 3, как и английская команда (`penalties.english_working_max_stars`); только из письма, без описания — не больше 4 (метка *E-mail only*, `penalties.email_only_max_stars`).

**Processed** — подвкладки *All manually* (что пользователь сделал сам: статус или жалоба) / Applied / Not now / Skipped, в debug ещё Reported / Auto-skipped / Hidden (статус и причина отсева в своей колонке). Ручные вкладки сгруппированы по дню действия, Auto-skipped и Hidden — по прогону. Заголовок вакансии в сайдбаре открывает её карточку здесь.
Под ними строка **Filters:** — выпадающие списки с множественным выбором по всему, что известно о вакансии:
причина отсева, источник, группа, Fit, ВНЖ и все факты, которые извлекает LLM (язык объявления, требуемые языки,
страна, город, формат, грейд, тип работодателя, сербское юрлицо, оформление и т.д.). Внутри одного списка — «или»,
между списками — «и». Рядом с вариантом — сколько таких вакансий в подвкладке. Фильтр применяется, когда список
закрывается; *Reset* — сбросить. Фильтры сохраняются при переключении подвкладок.
Слева от фильтров — **поиск** по текущей подвкладке (Enter) с выбором поля: везде / заголовок / работодатель / текст
(оригинал объявления) / причина отсева; регистр не важен, работает вместе с фильтрами, счётчики фильтров считаются
после поиска. Список источников в фильтре отсортирован по алфавиту, остальные — по числу вакансий. Вакансии сгруппированы по прогонам.
У отсеянных до LLM (правилами, бесплатно) фактов нет — у них значение «not analysed»; для них фильтруйте по
*Skip reason* (например «Ad in Serbian, Russian not required»).
*Return to feed* (клавиша `R`) — вернуть карточку (так исправляются ошибки отсева). «Not now» сам в ленту не возвращается.

**Debug** (переключатель справа сверху, запоминается в браузере) — у вакансий появляются номер `#id` (клик копирует номер
без `#`) и дата прогона, который её собрал, а в раскрытой карточке — разбор оценки и факты.
Справа от *Skip* — поле «why skip?»: причина сохраняется вместе с пропуском (Enter в поле = Skip) и видна в
Processed → Skipped. *Report* — окно жалобы на оценку (многострочный текст, ⌘↵): вакансия получает метку *Reported*, все
такие вакансии с текстами — в Processed → *Reported*; повторный *Report* открывает написанный комментарий для правки.
В Processed появляются бледные подвкладки *Auto-skipped* и *Hidden*: что отсеяли правила и что LLM сочла «не вакансией».

**Statistics** — сверху: токены за всё время, число вызовов LLM, число прогонов.
- *Sources* — последнее состояние каждого источника. Колонки: New (собрано свежих), Seen (просмотрено, включая
  старые), To feed (попало в ленту), Time. Статусы: `ok`, `truncated` (упёрлись в `max_pages` — нормально для
  первого прогона RVC Global), `error`, `not_configured` (нет пароля почты — это не ошибка), `disabled`.
  **Тревожные признаки (подсвечены):** HTTP 403 / 429, Captcha, Cloudflare challenge, Redirect to login,
  «Source showed nothing (usually it does)». Это значит, что сайт начал блокировать или сменил вёрстку.
- *Runs* — история прогонов: Started, Status, Duration, New, Tokens (sdk-python), ±% of 5h Pro Limit, Problems.
  Строка раскрывается в таблицу по источникам. Процент лимита подписки программно недоступен — колонка считает
  токены прогона / `claude_sdk.pro_5h_limit_tokens` из `llm.yaml` (откалибровано по claude.ai → Settings → Usage).
  Подробности по каждому вызову — в `data/token_log.jsonl`.
Если появилось «⚠ Claude CLI reported auth source …» — CLI пошёл не через подписку, а через платный ключ
(в окружении есть `ANTHROPIC_API_KEY`); уберите его из `~/.zshrc` или переключитесь осознанно.

## 9. Как сменить LLM

По умолчанию включён `codex_cli` с подпиской ChatGPT. Модели этапов заданы в `models.codex_cli` файла `config/llm.yaml`. Возврат на Claude — выбрать `claude_sdk` и перезапустить приложение. Подробности в [OPENAI.md](OPENAI.md).

Вся смена — в `config/llm.yaml` (+ ключ в `config/.env` для API). Код менять не нужно.

**(а) Другая модель Claude по подписке.** В `models.claude_sdk` поменяйте `scoring: haiku` на `sonnet`
(точнее, в ~8 раз дороже для лимита — см. EVAL.md). Для Sonnet/Opus очистите `claude_sdk.thinking:`.

**(б) Платный API Anthropic.**
1. Аккаунт и ключ: https://console.anthropic.com → Settings → **API Keys** → Create Key.
2. Баланс: Settings → **Billing** → пополнить (например, $10).
3. **Лимит расходов**: Settings → **Limits** → monthly spend limit ≈ $10/мес — чтобы не было сюрпризов.
4. В `config/.env`: `ANTHROPIC_API_KEY=sk-ant-…`
5. В `config/llm.yaml`: `provider: anthropic_api` (модели — в `models.anthropic_api`, по умолчанию `claude-haiku-5-5`).
6. Проверка: `.venv/bin/vacancy-retriever run --sources serbiawork --limit 3 --db data/dev.sqlite`, затем
   Statistics → Runs (или `data/dev_token_log.jsonl`).
Документация: https://docs.claude.com/en/api/getting-started , цены: https://www.anthropic.com/pricing .

**(в) Платный API OpenAI.**
1. https://platform.openai.com → **API keys** → Create new secret key.
2. **Billing** → добавить способ оплаты и пополнить; **Limits** → monthly budget ≈ $10.
3. В `config/.env`: `OPENAI_API_KEY=sk-…`
4. В `config/llm.yaml`: `provider: openai_api` (модели — `models.openai_api`, по умолчанию `gpt-5.4-nano`).
5. Проверка — как в (б). Документация: https://platform.openai.com/docs , цены: https://openai.com/api/pricing .

**(г) Подписка ChatGPT вместо Claude** (через Codex CLI) — пошагово в `docs/OPENAI.md`.

⚠ Интерфейсы консолей меняются; ищите разделы «API keys», «Billing», «Limits/Usage».
Цены в `llm.yaml → pricing` нужны только для оценки «сколько стоило бы по API» (в интерфейсе сейчас не показываются) — обновляйте по официальным страницам.

## 11. Частые поломки

| Симптом | Что делать |
|---|---|
| Statistics → Sources: `error` + «HTTP 403», «Cloudflare», «Captcha» у сайта | Сайт блокирует. Подождать день; если повторяется — `enabled: false`. Проверить: `check-sources --sources <id>` |
| Statistics → Sources: «Source showed nothing» | Сайт сменил вёрстку или адрес. Открыть сайт в браузере; починить сборщик (Claude + снимок страницы в `samples/html/<id>/` + тест) |
| Шапка: «N items waiting for evaluation (LLM limit or error)» | Кончился лимит подписки или нет сети. Ничего не потеряно — оценятся в следующем прогоне |
| Красная плашка «LLM: … not logged in / authentication» | Claude Code разлогинился: в Терминале выполнить `claude`, войти. Проверка: `claude auth status` |
| «Claude Code CLI not found» | `brew install --cask claude-code`, затем `claude` для входа. Или указать путь в `llm.yaml → claude_sdk.cli_path` |
| Иконка в меню-баре с ⚠ | Сервер не запущен: открыть Vacancy Retriever из Launchpad (или `scripts/start.sh`) |
| «Порт 18765 занят» | `VR_PORT=8800 scripts/start.sh` |
| Прогон «завис» | Cancel (двойной клик). Если сервер не отвечает — `scripts/stop.sh && scripts/start.sh`; незавершённый прогон откатится сам |
| `Configuration error: …` | Опечатка в `config/*.yaml` — сообщение говорит файл и поле |
| Нужны подробности | `logs/serve.log`, `logs/run.log`, `logs/server.out` |

Восстановление: `scripts/stop.sh`, заменить файл `data/vacancy_retriever.sqlite` копией, `scripts/start.sh`.

## 13. Правила проекта (для ассистентов)

- Только `telegram.me`, никогда `t.me`. linkedin.com никогда не открывать (заблокировано в HTTP-клиенте); публичные
  страницы LinkedIn (`linkedin_public_pages`) включает только сам пользователь в Settings: без рабочего прокси они не открываются.
- Всё живёт в папке проекта; ничего не писать вне неё. Зависимости — только `.venv` через `uv`.
- Настройки — в `config/`, не в коде. Интерфейс — на английском; саммари вакансий — на русском;
  документация и комментарии конфигов — на русском.
- LLM только извлекает факты; группы/звёзды/отсев считает `scoring/engine.py` по `rules.yaml`.
- Новый источник = сборщик + снимок + тест. Каждый упавший тест — блокер.
