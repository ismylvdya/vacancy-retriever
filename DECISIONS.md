# DECISIONS — самостоятельные решения при сборке v0

Формат: что решено · почему · какие были варианты. Решения пользователя ([РЕШЕНО] в задании) здесь не
пересматриваются — только то, что было на усмотрение или не описано.

## LLM

1. **Переменные `ANTHROPIC_API_KEY` / `ANTHROPIC_AUTH_TOKEN` из окружения CLI не удаляются.**
   Владелец машины сборки (Макс) явно попросил этого не делать во время сборки. Взамен приложение на каждом
   вызове читает из CLI `apiKeySource` и сохраняет его; если CLI пошёл не через подписку (значение не `none`),
   во вкладке Tokens появляется предупреждение. Проверено: на машине сборки `apiKeySource: none` (подписка).
   `config/.env` всё равно читается в объект настроек и в `os.environ` не попадает.
2. **JSON текстом + валидация вместо structured output CLI.** Замер: structured output требует 2 хода и
   ≈1070 токенов накладных расходов на вызов против ≈580 у текста. Ответ валидирует pydantic; при ошибке
   формата — повтор. Включается `claude_sdk.structured_output: true`.
3. **Системный `claude` вместо встроенного в колесо SDK.** Колесо `claude-agent-sdk` 0.2.165 несёт свой CLI
   (`_bundled/claude`), но пользователь логинится в системный. Порядок поиска: `llm.yaml → claude_sdk.cli_path`,
   затем PATH, затем `/opt/homebrew/bin`, `/usr/local/bin`, `~/.local/bin`, `~/.claude/local`. Процессы, запущенные
   не из терминала, имеют урезанный PATH — поэтому явные пути.
4. **Изоляция вызовов:** `tools=[]`, `setting_sources=[]` (не читаются CLAUDE.md, хуки, плагины пользователя),
   `strict_mcp_config` без MCP, `cwd=.cache/llm_cwd`, короткий свой system prompt, флаг
   `--no-session-persistence` (иначе каждый вызов оставлял транскрипт в `~/.claude/projects/`).
5. **`effort: low`, у Haiku `thinking: disabled`.** Замер на пачке из 5 вакансий: выход 5093 → 3298 токенов
   (−35%), категории идентичны. Для Sonnet мышление не отключается (может не поддерживаться) — в конфиге пусто.
6. **Модель по умолчанию — Haiku** по результатам eval (см. EVAL.md): 0 ложных скипов, 50/50 решений,
   ~8× экономнее для лимита Pro, чем Sonnet.
7. **Промпт оценки — по-английски** (меньше токенов, модели точнее следуют), саммари строго по-русски.
   Добавлены правила вывода, которые не являются «додумыванием»: объявление на русском → русскоязычная
   команда; ООО/₽/российский город → российский работодатель. Без них ~10 удалённых вакансий РФ-работодателей
   падали в группу 5. Поля со значением по умолчанию модель не выводит (экономия выхода).
8. **Пачки:** 10 одиночных вакансий или 5 многовакансионных постов/писем в одном вызове; не больше 2 вызовов
   одновременно. Письма идут отдельными пачками со своим этапом `scoring_email` (видно, сколько стоит
   отсутствие точных почтовых парсеров).
9. **API-провайдеры (`anthropic_api`, `openai_api`) — через httpx, без пакетов `anthropic`/`openai`.**
   Меньше зависимостей, один стиль кода, легко мокать в тестах; глобальные правила владельца машины
   предписывают не тянуть `anthropic` SDK. У Anthropic кэшируется system prompt (`cache_control`).
10. **Цена GPT-5.4 nano** ($0.20 / $1.25 за 1 млн) взята из сторонних трекеров цен: официальная страница
    OpenAI отвечает 403 без браузера. Цены Claude — из справочника моделей Claude API на 2026-10-06.

## Отбор и правила

11. **RVC: грейд берётся из текста первой строки («| Junior |»), а не из эмодзи.** На живой выборке 🟪
    встречался и с Junior (C++ 6000–18000 USD), и с Senior, и с Lead; тег поста — `#purple`. Это метка зарплаты,
    не грейда. Эмодзи используется только если текстового грейда нет: 🟨 → middle, 🟥 → senior.
    Рекламные посты RVC (без эмодзи-маркера или с partner-ссылкой walllet) — скрываются полностью.
12. **Предфильтр: стоп-слова грейда не применяются, если в заголовке есть junior/стажёр/младший.**
    Иначе «Quantitative Researcher Junior-Middle» уходил в отсев (найдено на живом прогоне). Ролевые
    стоп-слова (QA, 1С, бариста…) применяются всегда.
13. **Группа 5 по алгоритму ТЗ — «всё остальное».** В неё, кроме `confidence = low`, падают офисные вакансии
    вне Сербии (Москва, Париж) и категория `other` (дизайнеры и т.п.). Правило отсева «офис вне Сербии» в ТЗ
    нет, и добавлять его без пользователя я не стал — группа 5 свёрнута. **Вопрос к пользователю на v1:**
    отсеивать ли офис/гибрид вне Сербии и категорию `other`?
14. **ВНЖ «да» при обещанной помощи с ВНЖ** даже если юрлицо только «вероятно» — так требует пример №2 ТЗ.
15. **Дедуп сырых элементов:** ссылка → хэш нормализованного текста → нечёткое сравнение
    (`token_set_ratio ≥ 90`, тексты > 200 символов) **только между разными источниками** и только среди
    текстов похожей длины (±25%). Шаблонные посты одного канала (RVC) иначе склеивались бы между собой.
16. **Дедуп вакансий:** точное совпадение «компания+должность» (без юр. формы и слов грейда) склеивает код;
    «серая зона» — компании похожи (≥85) и должности похожи (≥75), либо компания неизвестна, а должности почти
    совпадают (≥95) — решает LLM пачками по 20 пар. Внутри одного поста-дайджеста вакансии не склеиваются.

## Хранилище и прогон

17. **Staging = флаг `staged` + `run_id` в тех же таблицах**, а не отдельные таблицы-копии. Прогон никогда не
    меняет закоммиченные строки: изменения статусов старых элементов и курсоры пишутся в
    `raw_status_updates` / `run_cursors` и применяются одной короткой транзакцией при коммите. SQLite в WAL.
18. **Курсоры:** Telegram — id последнего поста; сайты и почта — время старта прогона минус 1 час.
    Курсор источника сдвигается только при статусе `ok`/`truncated` и только при коммите.
19. **Один прогон на машину** — файловая блокировка `data/run.lock` (fcntl). Прогресс пишется в
    `data/progress.json`, поэтому веб-интерфейс видит и прогон, запущенный из терминала.
20. **Почтовые флаги — после коммита, в памяти процесса прогона.** Письмо, разбитое на несколько вакансий,
    помечается только когда ни одна из них не ждёт LLM. Ошибка IMAP при пометке не роняет прогон, а
    показывается в Health («Could not label / move processed e-mails»).
21. **Тревога «источник ничего не показал»** считается по `seen` (сколько элементов источник реально отдал,
    включая уже известные), а не по числу новых: иначе тихий канал без новых постов выглядел как блокировка.
22. **«Expired»** (необработанные старше 30 дней уходят в Auto-skipped) применяется при коммите каждого прогона.

## Источники

23. **Отключены:** infostud и startuj (Cloudflare JS-челлендж, 403 даже на robots.txt), helloworld (WAF-блок
    Cloudflare), hirehi (TCP-таймаут на 80/443, 4 попытки за 40 минут). Внешний IP машины сборки
    геолоцировался как Сингапур — **из Сербии стоит попробовать ещё раз**; но JS-челлендж infostud
    обычным HTTP-клиентом не проходится. Сборщики для них не писались.
24. **ovdejobs:** фильтр категорий выключен — часть подходящих вакансий («Маляр на мебельное производство»)
    без категории, индекс FacetWP частично устарел. Даты — через публичный WP REST (`/wp-json/wp/v2/jobs`).
25. **youngjunior, hirify, talentmove** собираются через машиночитаемые эндпоинты самих сайтов (JSON API,
    API за Nuxt-страницами, RSS) — стабильнее вёрстки. **changellenge** — HTML. hirify сортирует по дате
    обновления, а не публикации — учтено в остановке по курсору.
26. **getmatch/habr/geekjob — малый объём.** Junior + data за 30 дней: getmatch ~3, habr ~2, geekjob ~19.
    Фильтры оставлены «как в задании»; расширить можно в `params`.
27. **Докачка описаний** — только для доменов из `detail_domains` в `sources.yaml`. Ссылки из Telegram-постов
    не открываются, linkedin.com блокируется на уровне HTTP-клиента.

## Интерфейс и процессы

28. **Серверные шаблоны Jinja2 + ванильный JS** без сборки. Статус опрашивается раз в 1.5 с во время прогона,
    раз в 15 с в покое. Версия статики = хэш файлов (иначе браузер держал старый app.js после обновления).
29. **Отмена прогона — двойной клик** («Click again to cancel» на 4 с) вместо `confirm()`: нативные диалоги
    ненадёжны во встроенных браузерах.
30. **Меню-бар:** заголовок `🦮` + число вакансий в ленте, во время прогона — процент; пункт «Open».
    Иконка Telegram на карточке — аватар канала с маленьким значком Telegram; сайты — favicon.
31a. **Порт по умолчанию — 18765**, а не 8765: 8765 занимает AnkiConnect (популярный плагин Anki).
    Поменять: `VR_PORT=… scripts/start.sh`.
31. **«Скопировать полный текст»** = текст первичного источника (для сайтов — докачанное описание) + ссылка.

## После переноса на машину пользователя (2026-10-14)

33. **RVC: отсев «нет русского и не Сербия» до LLM** (решение пользователя по открытому вопросу №1, вариант «а»).
    Правило `prefilter.rvc_require_russian_or_serbia` в `rules.yaml`; маркеры Сербии — `rvc_serbia_markers`.
    Посты без строки «Требуемые языки» не трогаются. Объём RVC Global в `sources.yaml` исправлен на ~1000/день.
34. **Офис/гибрид вне Сербии — отсев** (решение пользователя по открытому вопросу №2): `drop_office_outside_serbia`
    в `rules.yaml`, причина «Office outside Serbia». Удалёнка и неизвестная страна не трогаются. Категория `other`
    остаётся в группе 5.
35. **Первый прогон — 1 день** (`first_run_days: 1`), решение пользователя.
36. **Почта отключена** (`enabled: false` у gmail и yandex) — пользователь пока не настраивал рассылки.
37. **infostud и startuj включены:** с IP пользователя Cloudflare их не блокирует (200). Один сборщик `infostud`
    (данные Next.js, фильтр сайта `onlineAfterDate`); startuj — это раздел «Poslovi za mlade» того же infostud
    (`youthPosition=1`). **helloworld** — та же платформа и те же id вакансий, отдельно не собирается.
    **hirehi** открывается, но по фильтру «Сербия» почти одни продажи/PM — сборщик не писался.
38. **Языковой фильтр до LLM** для источников с `serbian_needs_russian: true` (infostud, startuj): после докачки
    описания объявление на сербском без упоминания русского сразу уходит в Auto-skipped («Ad in Serbian,
    Russian not required») — то же правило, что применил бы движок, но без токенов. Эвристика `looks_serbian`.
39. **Окружение перед вызовом `claude`:** удаляются `ANTHROPIC_*`, `CLAUDE_*` (кроме `CLAUDE_CONFIG_DIR`) и
    `CLAUDECODE`, иначе CLI, запущенный из другой сессии Claude Code, мог бы пойти мимо подписки
    (требование ТЗ, в v0 не было реализовано).
40. **«Нужен сербский, русский не требуется» не срабатывает для объявлений на русском** (2026-10-14): в первом
    прогоне Haiku приписала сербский русскому объявлению TRUSTONE DOO (в тексте язык не упомянут). Код больше не
    отсеивает по этому правилу при `ad_language: ru`, а промпт требует ставить `serbian_required` только при прямом
    упоминании языка (+ пример №11).
41. **Почта: три ответа точного парсера** (2026-10-26): вакансии / известный шаблон без вакансий (скрыт без LLM,
    письмо помечается после прогона) / незнакомый шаблон (письмо не трогается, в LLM не идёт, пометка в Statistics).
    Сломанный парсер тоже не уходит в универсальный разбор — токены не тратятся на мусор. Отправитель сравнивается
    в приложении, а не IMAP SEARCH FROM (Яндекс не находил `hh.ru` в `noreply@hh.ru`).
42. **Id вакансии из письма = id на сайте** (`linkedin:<id>`, `hh:<id>`…): одна вакансия из 3 писем собирается
    один раз; письмо, все вакансии которого уже собраны, скрывается и помечается.
43. **hh.ru:** «Подходящие вакансии для резюме» пропускаются — формат работы неизвестен, страница hh отвечает 406
    клиентам-не-браузерам (обходить защиту не стали), и офисы в Москве попадали бы в группу 3. Вместо них —
    автопоиски с фильтром «Удалённая работа» (вакансиям ставится подсказка `work_format: remote`).
44. **Отсев по странице вакансии до LLM:** VK Internship («Набор закрыт», офис/гибрид в городе вне Сербии) и
    Changellenge (город вне Сербии, формат не удалённый). Хук `Collector.detail_skip_reason`.
45. **LinkedIn «Serbia (Remote)»** = работа в Сербии (группа 1, ВНЖ «likely») — решение пользователя 2026-10-26.
46. **Ссылки с токенами входа** (hh `loginkey`, SuperJob `?i=`) не сохраняются — только чистый адрес вакансии;
    образцы писем маскируются при выгрузке (`export-email-samples`).
47. **P1, 26.10.2026.** «English team» — не больше 3 звёзд (`penalties.english_working_max_stars`); грейд, написанный
    словом в тексте объявления, отсеивается так же, как в заголовке (`drop_seniority_from_text`; «опыт от N лет» —
    не грейд, промпт уточнён).
48. **Дедуп без LLM** (`llm.yaml dedup_with_llm: false`): похожие пары остаются двумя карточками; одинаковые
    «название + компания» из разных источников и пост канала, первая строка которого — название вакансии с сайта,
    а в тексте её компания, склеиваются до LLM; оригиналом становится карточка сайта (богаче текст).
49. **Зарплата:** разбирается кодом из `salary_text` (диапазоны, k/тыс., час/год, 14 валют; без валюты — без
    пересчёта); рубли — по курсу ЦБ РФ на день сбора (`data/rates/`, запасной источник open.er-api.com — у Google нет
    API); отсев, если нижняя граница в месяц > 175 000 ₽ (`rules.yaml salary.max_floor_rub`).
50. **getmatch / Habr без фильтра грейда:** с Junior/Intern было ~1 вакансия в неделю. Грейд из данных Habr и слова
    в заголовке отсеивают middle/senior/lead до LLM; в LLM доходят вакансии без грейда (≈ 15 + 23 в неделю).
    GeekJob не расширяли — никакие фильтры не добавили вакансий.
51. **Интерфейс:** панель Run ▾ (период в сутках + группы источников), прогресс по этапам с полосой иконок
    источников, Undo/Redo (история во вкладке браузера), закреплённые шапки, лента скрыта во время прогона, отдельные
    блоки групп, шорткаты →/← для Applied/Skip, колонка шире (поля = ⅔ прежних).
52. **LinkedIn: публичные страницы вакансий без входа** (2026-10-27, по просьбе пользователя): письма дают только
    название, компанию и город. Отдельный анонимный загрузчик (`collectors/linkedin_guest.py`): адрес из номера вакансии
    (ссылки писем с токенами входа не открываются), без cookies / Referer / редиректов, только страницы вакансий из
    писем, ≤ 40 за прогон, 4–8 с; первый отказ — пауза до завтра, без повторов, прокси и обходов. Аккаунт не участвует;
    остаточный риск — временное ограничение гостевых страниц для домашнего IP. Включается флагом после проверки.
